# Aircraft Optimization Guide

## Что лучше: датасет или RL?

Для этой задачи лучше начинать не с обучения с подкреплением.

Почему:

- У нас не игра и не последовательное управление, а статическая оптимизация геометрии.
- Каждая оценка конструкции дорогая, потому что требует аэродинамического расчета.
- RL обычно требует очень много эпизодов и отдельной среды.
- Здесь гораздо эффективнее работает прямой поиск по параметрам и, при необходимости, суррогатная модель по датасету.

Практический порядок такой:

1. Сначала прямая оптимизация геометрии.
2. Потом генерация датасета.
3. Потом суррогатная модель для ускорения поиска.
4. RL только если позже захочется обучать агента делать последовательные изменения конструкции шаг за шагом.

## Что уже реализовано

В [optimizer.py](/Users/aleksandrvorobev/Documents/skat/optimizer.py) есть:

- параметризация крыла, ПГО, горизонтального и вертикального оперения;

- диэдр крыла;
- общую хорду крыла;
- корневую, среднюю и концевую хорду крыла;
- общий твист крыла;
- продольное положение ПГО;
- поперечное положение ПГО;
- вертикальное положение ПГО;
- размах ПГО;
- стреловидность ПГО;
- общую хорду ПГО;

- твист ПГО.
- положение, размеры и твист горизонтального оперения;
- положение, размеры и высоту вертикального оперения.

## Быстрый старт

Базовая оптимизация:

```bash
python3 /Users/aleksandrvorobev/Documents/skat/optimizer.py optimize
```

Оптимизация по своей конфигурации из GUI:

```bash
python3 /Users/aleksandrvorobev/Documents/skat/optimizer.py optimize --config /path/to/aircraft_config.json
```

Сгенерировать датасет:

```bash
python3 /Users/aleksandrvorobev/Documents/skat/optimizer.py sample --samples 200 --output dataset.jsonl
```

Запустить суррогатный поиск по датасету:

```bash
python3 /Users/aleksandrvorobev/Documents/skat/optimizer.py surrogate --dataset dataset.jsonl
```

## Что считается "оптимальностью" сейчас

Сейчас оптимизатор пытается найти конструкцию, у которой:

- хороший `L/D`;
- `CL` близок к целевому;
- `Cm` меньше по модулю;
- размеры крыла и ПГО остаются физически разумными;
- геометрия остается разумной.

В выводе оптимизатора теперь также показываются размеры:

- размах крыла;
- площадь крыла;
- корневая и концевая хорда крыла;
- удлинение крыла;
- те же метрики для ПГО.

Это не финальная физическая постановка. Дальше её стоит уточнить под миссию:

- крейсер;
- взлет/посадка;
- устойчивость;
- ограничение по размаху;
- ограничение по площади крыла;
- ограничение по массе.

## Следующий правильный шаг

Лучше всего дальше сделать целевую функцию под конкретную задачу полета. Например:

- скорость;
- масса;
- требуемый `CL`;
- допустимый размах;
- приоритет: максимальный `L/D` или лучшая устойчивость.

После этого оптимизация станет гораздо полезнее, чем просто "сделай форму лучше".
